# 動物パズル UI 全面刷新 設計書

作成日: 2026-09-11

## 1. 背景

参考アプリ（にゃんどく / `C:\claude\test`）と実画面を並べて比較した結果、品質差の原因は
装飾の巧拙ではなく**構造**にあることが分かった。

| 項目 | にゃんどく | 動物パズル（現状） |
|---|---|---|
| 盤面 | 白カード＋角丸セル＋gap 6px。マス目が見える | 草の写真テクスチャ。**マス目が一切見えない** |
| 素材 | 自作 SVG（同一パレット・同一線幅） | 生成画像 11 種。絵柄・線幅・光源・彩度がバラバラ、リスに白フチが残存 |
| 動き | Motion のバネ、配置時の pop、クリア時の跳ね | `PopIn` のみ。追従・スナップ・却下フィードバックなし |
| 情報 | 進捗・難易度が常時見える | **条件（パズルの本体）が `▼` の中に隠れている** |
| 座標 | 盤の矩形から毎回 `cellFromPoint` で計算 | `measureInWindow` の非同期結果を 3 箇所で保持して突き合わせ |

`stage-1` の実画面では、**どこが 1 マスなのか分からない**まま動物を放り投げる操作になっている。

### 「一度置いたピースが動かせない」の原因

`stage-game-view.tsx` は `content.rect` / `boardArea.rect` / `trayArea.rect` を
`measureInWindow` の**非同期コールバック**で個別に `useState` に保持し、ドラッグ開始時に
測り直して終了時に読む。この間にスクロール・再レイアウト・フォント読み込みが挟まると
判定矩形がずれる。加えて盤上のピースは `PopIn`（Animated）の内側にいるため、
アニメーション途中に掴むと**動いている最中の座標**が返る。

個別に潰すのではなく、**盤の `getBoundingClientRect()` からその場で計算し、値を一切
保持しない方式**（参考アプリの `cellFromPoint`）に置き換えて根を断つ。

## 2. 目的

1. 参考アプリと同じ質感・同じ操作の確かさに到達する。
2. 中途半端な写実素材を全廃し、**シンプルで洗練された自作 SVG** に統一する。
3. パズルの本体である条件を常時見えるようにする。
4. 「反応しない」を構造的に起こらなくする。

### 非ゴール

- ゲームルール・難易度設計の変更。**engine と 40 ステージの内容は一切変えない。**
- ステージ生成器（`scripts/generate-open-stages.ts`）の変更。
- ネイティブアプリ化。現状の公開先は GitHub Pages のみで、ネイティブビルドの実績はない。

## 3. 技術構成の移行

Expo（React Native Web）から **Vite + React 19 + TypeScript** へ移行する。
`C:\claude\CLAUDE.md` の技術既定値、および参考アプリと同じ構成。

移行の理由は見た目ではなく操作性にある。「反応しない」は RN-Web の
`PanResponder` / `measureInWindow` 層に起因しており、参考アプリの手法
（CSS Grid・Motion のバネ・`@use-gesture` の経路補間・WebAudio）は
React Native View の上では再現できない。

### 移行の内訳（実測）

| 扱い | 対象 | 行数 |
|---|---|---|
| **そのまま移植** | `src/engine/**`、`src/levels/stages.ts`、`src/lib/{condition-text,stage-design-checks,stage-difficulty,stage-submission}.ts`、`__tests__/**` | 約 2,900 |
| **書き換え（薄い）** | `src/storage/*` — AsyncStorage → localStorage | 90 |
| **捨てる** | `src/app/**`、`src/components/**`、`src/theme.ts`、`src/lib/animal-art.ts`、`assets/images/{animals,terrain,fence}` | 1,500 + 21 ファイル / 約 2.7MB |
| **新規** | `src/ui/**`、`src/art/**`、`src/core/{sfx,router}.ts`、`src/ui/styles.css` | — |

`src/engine`・`src/levels`・`src/lib` に react-native / expo の import は
**1 つも無い**ことを確認済み（`src/lib/animal-art.ts` のみが例外で、これは捨てる）。

### storage の書き換え方針

`loadProgress` / `recordClear` / `listCustomStages` などの **async シグネチャを維持**する。
localStorage は同期だが `Promise.resolve()` で包み、呼び出し側の形を変えない。
移行時の差分を storage の内部だけに閉じ込めるため。

### ルーティング

expo-router を廃し、**ハッシュルーティング**（`#/game/stage-1`）の自前ルータ（約 40 行）にする。

- GitHub Pages の 404.html フォールバックが不要になる
- `base` パスとルートパスの二重管理が消える
- 既存の `/game/stage-1` 形式のブックマークは切れる（公開直後のため影響は小さいと判断）

ルートは 5 つ: `#/`（一覧）、`#/game/:stageId`、`#/my-stages`、`#/editor`、
未知のハッシュは `#/` にフォールバック。

### ビルドとデプロイ

- `vite.config.ts` の `base: '/animal-puzzle/'`（リポジトリ名と必ず一致させる）
- `scripts/deploy.mjs` は参考アプリのものを流用。`dist/` を使い捨てリポジトリにして
  `gh-pages` へ orphan commit を 1 つ force push する
- `.nojekyll` は deploy スクリプトが毎回書き出す（`AGENTS.md` の警告に対応）
- `npm run deploy` = `tsc --noEmit && vite build && node scripts/deploy.mjs`

`AGENTS.md` の Expo 前提のデプロイ手順は、この構成に合わせて書き換える。

### 4.2 種の色（11 色）

**測定に基づく決定。** ステージ内容を集計したところ:

- 1 ステージあたりの種数は 3〜**8**（6 種が 17 面で最多）
- 実際に同居する種のペアは **54 / 55**（`ゾウ + ゴリラ` のみ非同居）

つまり **11 色すべてを相互に見分けられる必要がある**。写実的な色
（ライオン＝黄、キリン＝黄、ヒョウ＝黄、ゾウ＝灰、サイ＝灰、ゴリラ＝黒…）では
必ず衝突するため、**色は「種のラベル」と割り切り、色相を等間隔（32.7°）に配る**。

明度と彩度を固定するのが要点で、これをやらないと「どれか 1 色だけ浮く」盤面になる。

```
面（駒）   oklch(0.70 0.12 H)
ふち（下辺） oklch(0.50 0.085 H)
```

|---|---|---|---|---|---|
| `monkey` | サル | 25 | `#DF7F78` | `#8D4F4A` | 5.3:1 |
| `squirrel` | リス | 58 | `#D68A4D` | `#87562F` | 5.4:1 |
| `lion` | ライオン | 90 | `#BB9B39` | `#766122` | 5.6:1 |
| `giraffe` | キリン | 123 | `#90AA51` | `#5A6B31` | 5.7:1 |
| `crocodile` | ワニ | 156 | `#58B47F` | `#35724E` | 5.9:1 |
| `oxpecker` | ウシツツキ | 189 | `#0BB6AE` | `#07726D` | 5.9:1 |
| `zebra` | シマウマ | 221 | `#27AFD3` | `#176E85` | 5.8:1 |
| `gorilla` | ゴリラ | 254 | `#68A1E7` | `#406593` | 5.6:1 |
| `rhino` | サイ | 287 | `#9A92E5` | `#605B91` | 5.4:1 |
| `elephant` | ゾウ | 320 | `#BF85CD` | `#795381` | 5.3:1 |
| `leopard` | ヒョウ | 352 | `#D77EA6` | `#884E68` | 5.2:1 |

検証済み:

- 全 22 色が **sRGB 色域内**（L=0.70 で全色が収まる最大 C は 0.124、L=0.50 で 0.090）
- 最も近い 2 色（リス vs ライオン）で **ΔE_ok = 0.066 = 弁別閾の 3.3 倍**
- シルエット `#3B2E2B` とのコントラストは**最低 5.25:1**

CSS には `oklch()` をそのまま書く（`--sp-lion: oklch(0.70 0.12 90)`）。
設計意図が値そのものに残り、色相を変えたくなったときに 1 数値で済む。

### 4.3 ブロック（置けないマス）

置けないマスは**すべて暗いニュートラル**にし、種類は**白抜きアイコン**で区別する。
これで種の 11 色とマスの色が競合しない。彩度を C≤0.05 に抑えることで、
駒（C=0.12）とは別レイヤーに見える。

| 種別 | 色 | アイコン | 白アイコンとの比 |
|---|---|---|---|
| `wall` 茂み | `oklch(0.42 0.02 60)` = `#564B42` | なし（無地） | 8.5:1 |
| `water` 水 | `oklch(0.45 0.05 230)` = `#375B6C` | 波 2 本 | 7.3:1 |
| `tree` 木 | `oklch(0.45 0.05 145)` = `#445D44` | 葉 1 枚 | 7.3:1 |

置けるマス（`land`）は `#EBE4DC`。`void` はマスを描かない（背景が透ける）。

## 5. 盤面

### 5.1 レイアウトが 1px も動かないこと

参考アプリが踏んだ罠を最初から塞ぐ。

- `.board` に `grid-template-columns: repeat(var(--cols), 1fr)` と
  `grid-template-rows: repeat(var(--rows), 1fr)` を**両方**書く
- セルに `min-width: 0; min-height: 0`
- **駒は grid に一切参加させない。** `position: absolute` で盤の内側に重ねる

これにより、駒を置いても消しても grid の計算結果が変わらない。

### 5.2 寸法（JS を使わない）

参考アプリは正方形固定だが、動物パズルの盤面は 2×4 〜 8×8 と縦横比が変わる。
CSS の `aspect-ratio` で完結させ、セルサイズの JS 計算を廃止する。

```css
.board {
  --ar: calc(var(--cols) / var(--rows));
  width: min(92vw, 460px, calc(var(--board-max-h) * var(--ar)));
  aspect-ratio: var(--ar);
}
```

`--board-max-h` は `52dvh`。縦長の盤面（2 列 × 8 行）でも高さが先に効いて収まる。

駒の位置も CSS だけで出す。セル幅を式として持つ。

```css
--cw: calc((100% - var(--pad) * 2 - var(--gap) * (var(--cols) - 1)) / var(--cols));
left: calc(var(--pad) + var(--c) * (var(--cw) + var(--gap)));
width: calc(var(--w) * var(--cw) + (var(--w) - 1) * var(--gap));
```

複数マスの駒（ドミノ・2×2）は **gap をまたぐ 1 枚の角丸ブロック**になる。
形が主張し、「2 マス分の生き物」であることが一目で分かる。

### 5.3 当たり判定

JS が座標を持つのはここだけ。**毎イベント `getBoundingClientRect()` を取り直す。**

```
inner = rect.width - PAD * 2
step  = (inner - GAP * (cols - 1)) / cols + GAP
col   = clamp(floor((clientX - rect.left - PAD) / step), 0, cols - 1)
```

値をキャッシュしないので、スクロール・回転・リサイズ・フォント読み込みのいずれでもずれない。

## 6. 動物の表現

`viewBox="0 0 24 24"` の**単色シルエット**を 11 種、`fill="#3B2E2B"`。

- パスは 3〜6 本まで。細部を描かない
- 駒ブロックの上に **62%** の大きさで中央配置
- 6×6 の小さいマス（実寸 40px 程度）でも輪郭が潰れないこと
- 形（1×1 / 2×1 / 1×2 / 2×2）は**駒の外形**が担う。シルエットは「何の動物か」だけを伝える

横長（`domino_h`）の種はシルエットも横長の構図、縦長（`domino_v`）は縦長の構図にして、
外形とシルエットの向きを一致させる。

11 種が同時に並ぶことがあるため、**輪郭のシルエットだけで区別できること**を
実装時にブラウザで並べて確認する（色に頼らない）。特に区別が要るのは
ライオン / ヒョウ（たてがみの有無）、サル / ゴリラ（体格）、サイ / ゾウ（角と鼻）。

## 7. 操作モデル

| 動作 | 挙動 |
|---|---|
| 動物カードをタップ | 選択。**その駒が収まるマスが盤面で光る** |
| 光ったマスをタップ | 確定して配置 |
| 盤上の駒をタップ | その駒を選択（置き直しの起点） |
| ドラッグ | 7px 超えたらドラッグと判定。盤の矩形から毎回セルを計算してスナップ |
| 置けない場所で離す | 駒がバネで元位置へ戻り、盤が左右に短く振れる |
| 盤の外で離す | トレイに戻る |
| 盤の余白をタップ | 選択解除 |

タップ／ドラッグの閾値 7px は参考アプリと同値。指はまっすぐ動かないため、
これが小さすぎると普通のタップが誤ってドラッグになる。

「置けるマス」は engine の `placeAnimal` が状態を変えるかどうかで判定する。
UI 側に配置可否のロジックを一切持たない（engine と二重管理しない）。

ハイライトの見せ方は**色ではなく形**にする。種の 11 色がすでに全色相を使っているため、
黄色などで光らせると種の色と競合する。マス背景を `#F5EFE6` に上げ、
**中央に小さな丸（ink 20%）**を出す。

触覚は `navigator.vibrate`: 配置 `8`、却下 `[12, 40, 12]`、クリア `[18, 60, 18, 60, 30]`。

## 8. トレイ＝条件カード（統合）

盤面の下に 1 列。1 枚のカードに、その種の情報をすべて入れる。

```
[色ブロック+シルエット]  ライオン ×2   ○ リスのとなりに置けない
[色ブロック+シルエット]  リス   ×1     ✗ ライオンのとなりに置けない
```

- **残数**: まだ置いていない数。0 になったらカードを淡くする（消さない。条件は見え続ける必要がある）
- **条件**: `lib/condition-text.ts` の文言をそのまま使う
- **達成状況**: `isSpeciesConditionSatisfied` の結果を ○ / ✗ で出す
- **選択中**: アウトライン
- **違反中**: カードを赤くする。**盤上の赤い駒とカードの赤が対応**し、なぜダメなのかが分かる
- カードをタップ = その種の未配置の駒を 1 つ選択

ステージ限定ルール（`stage.rules`）がある場合は、末尾に「このステージのやくそく」カードを 1 枚足す。

## 9. 動き（Motion）

| 場面 | 指定 |
|---|---|
| 駒を置く | `spring(stiffness 620, damping 20, mass 0.7)`、`scale 0 / rotate -22` から |
| 駒を取り除く | `scale 0, opacity 0`, 0.12s |
| 却下 | `x: [0, -5, 5, -3.5, 3.5, 0]`, 0.34s |
| クリア | 置いた順に `y: [0, -13, 0]`、0.08s ずつ遅延、その後オーバーレイ |
| ボタン押下 | `transform: scale(0.9)`, 0.15s |

`@media (prefers-reduced-motion: reduce)` ですべて無効化する。

オーバーレイを閉じるアニメーション中にクリックを吸わせない
（`exit={{ opacity: 0, pointerEvents: 'none' }}`）。

## 10. 音

WebAudio で合成する。**音声ファイルは持たない**（読み込みゼロ・容量ゼロ・遅延ゼロ）。

| 場面 | 音 |
|---|---|
| 選択 | 短く軽いクリック |
| 配置 | 木質のポン |
| 却下 | 低い 2 音 |
| クリア | 上行アルペジオ |

ヘッダにミュートボタン。状態は localStorage（`animal-puzzle:muted`）。
`AudioContext` は最初のユーザー操作で生成する（自動再生ポリシー対策）。

## 13. テスト

既存の engine テスト（2,783 行）は**そのまま通す**。テストランナーは jest-expo から
Vitest へ移す（`describe` / `it` / `expect` の API は互換なので本文は変更しない見込み）。

追加するのは 3 つだけ。UI の見た目はテストせず、ブラウザで実測して確認する。

1. **座標 → セル変換の境界値**: `cellFromPoint` が gap の上・端・矩形外で正しい値を返すか
2. **駒の外形**: `domino_h` / `domino_v` / `square2x2` の幅・高さの式が gap をまたぐか
3. **storage**: localStorage 版が旧データ形式を読めるか、容量超過で壊れないか

## 14. 検証（実装後にブラウザで確認する項目）

1. **盤面が動かない**: 駒を置く・取るを 20 回繰り返して、セルの矩形が 1px も変わらないこと
2. **11 種のシルエットが色なしで区別できる**: グレースケールで並べて確認
3. **8 種が同時に出るステージ**（5 面ある）で色が混乱しないこと
4. **置いた駒を必ず動かせる**: 配置直後（アニメーション中）に掴んでも掴めること
5. **スクロール後にドラッグしてもずれない**
6. 縦長（2×8）・横長（8×2）・正方形（8×8）の 3 形状で盤面が画面に収まること
7. モバイル幅（375px）で盤面・カード列が縦スクロールなしに収まること
